In Argus, the validated Pull Request URL opens in a Browser Tab owned by this Workspace. Reopening the same URL reuses that Workspace’s tab. Refreshing status never changes Workspace selection or terminal focus.

Recommendation

Start with A. Keep the workflow quiet.

It answers “which PR, and does it need attention?” without increasing row height or requiring the Changes View. The badge opens a compact native summary; the actual Pull Request opens in the originating Workspace’s Browser Tab.

Keep the leading Agent Status / attention icon and the running-process count intact. Keep PR lifecycle, CI/review signals, and refresh health independent.

Implementation plan

  1. Extend the existing GitHub boundary

    Reuse Argus’s bounded, noninteractive gh runner and provider-qualified identities. Add branch discovery and a small read-only status query; keep intake behavior unchanged.

  2. Match the actual worktree context

    Read current branch/HEAD from git worktree list --porcelain, not the saved Workspace subtitle. Validate repository and fork identity. Ambiguous matches stay ambiguous.

  3. Add one runtime status model

    Key results by Workspace and immutable context. Coalesce requests, cap concurrency, pause in the background, and discard late results after branch switches or Workspace removal. No persisted provider state.

  4. Ship one visual direction

    Implement A’s badge, accessible summary, scoped Open/Copy/Refresh actions, and a “Show Pull Request status” setting. B and C are alternatives, not additional settings.

  5. Verify, then promote the contract

    Fixture tests for lookup, lifecycle/check mapping, stale data, races, and no persistence. Native keyboard/VoiceOver and narrow-width checks. Run lint and app tests; update the spec and add a superseding ADR.

The VS Code Agent Manager tries current-branch lookup, explicit branch, then an exact-head SHA fallback. It shows a colored PR-number badge and separate check/review signals. A separate toolbar opens its full PR inspector.

Borrow the small status surface and refresh cadence—not the entire review system. Argus already has the CLI runner, timeout, output limits, repository validation, and native Workspace ownership needed here.

Improve on the reference: explicitly label stale data, distinguish “no PR” from lookup failure, do not conflate pending CI with PR lifecycle, and keep every action keyboard-accessible.

Scope and correctness boundaries
  • Named Project Worktree Workspaces only. GitHub through the active CLI context; no new dependencies or credential store.
  • Open, draft, merged, closed; aggregate checks/review; freshness. No comments, merge actions, check logs, notifications, or Review Work Mode.
  • All-state, bounded discovery with explicit repository/branch. Do not take the first same-name fork match or attach an old merged PR to a reused branch.
  • Selected refresh every 15 seconds, all eligible Workspaces every 120 seconds; confirmed no-match at most every 60 seconds. Manual refresh bypasses caches.
  • Keep matching cached data on failure, visibly stale. Missing CLI/authentication has an inline recovery message, never an installation prompt or modal storm.
  • Read-only status must not fetch, rename, checkout, mutate Git state, alter local Changes counts, or redirect focus.
